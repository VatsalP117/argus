Lesson 2: Parquet And DuckDB

Skill: describe how Argus can query large file-backed data without first loading it into an app database.

Parquet is columnar: values from the same column are stored together. Analytical questions often need a few columns across many rows, so columnar storage can avoid reading irrelevant fields. DuckDB is the local SQL engine that can query those files directly.

The One Thing

Argus treats files as queryable data sources. DuckDB can read Parquet files directly, including remote files when configured with the right extension. This makes a bounded archive scan feel like SQL over a table, even though the input is a file shard.

SELECT subreddit, count(*) AS rows
FROM read_parquet('data/tmp/candidates/*.parquet')
GROUP BY subreddit
ORDER BY rows DESC;

Repo anchors: sql/discovery/validate_hf_duckdb_access.sql, sql/discovery/inspect_archive_schema.sql, and the Python DuckDB adapters in scripts/dev/.

Fullstack Bridge

Think of DuckDB as an embedded analytical database engine inside the local process, not as a hosted database server. The important unit is often a file path plus SQL, not a network connection plus ORM model.
