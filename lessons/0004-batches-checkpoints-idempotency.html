Lesson 4: Batches, Checkpoints, Idempotency

Skill: identify whether rerunning a data command is safe.

Argus processes bounded work units. A batch might be one manifest entry, one shard, or one staged output. A checkpoint records enough information to know whether a rerun is the same work or a dangerous mismatch.

The One Thing

Idempotency means "running the same command again should not corrupt or duplicate the result." In Argus, this is enforced with checkpoint reuse, config hashes, source identity checks, output checksums, and explicit statuses like skipped_existing.

Repo anchors: cmd/scan-candidates/main.go, internal/candidate/checkpoint.go, state/checkpoints/.

Fullstack Bridge

A normal API endpoint might use an idempotency key to prevent duplicate payments. A data pipeline uses checkpoints and checksums to prevent duplicate or mismatched processing.
