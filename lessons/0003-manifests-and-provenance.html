Lesson 3: Manifests And Provenance

Skill: explain why a data pipeline needs pinned input definitions.

A manifest is Argus' exact work order. It says which archive repo, revision, month, record type, shard path, source identity, and byte size belong to a run. Without it, a later result cannot prove what input it came from.

The One Thing

Provenance is not a nice-to-have. In Argus, every retained document must be traceable back to the remote source and the pipeline artifacts that selected it. The manifest is the first link in that chain.

Repo anchors: cmd/manifest-builder/main.go, internal/manifest/manifest.go, configs/pipelines/pilot-travel-q1-2021.yaml.

Fullstack Bridge

A manifest is like a lockfile for data inputs. It prevents "it worked on my dataset" by making the dataset itself part of the recorded build context.
