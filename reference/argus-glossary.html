Argus Data Engineering Glossary

This is the compact vocabulary map for onboarding. When a lesson uses one of these terms, this is the meaning to keep in mind inside Argus.

Archive

The remote, recoverable upstream source. In Argus this is historical Reddit data exposed as versioned Parquet shards.

Parquet

A compressed columnar file format. Argus uses it for remote archive reads and temporary local staging because analytical queries often need only selected columns.

DuckDB

An embedded analytical SQL engine. Argus uses it locally for remote Parquet scans, local transformations, validation SQL, and the durable research corpus.

Manifest

A reproducible work order that pins exact source shards, revisions, identities, and byte sizes. It is the data-pipeline version of "here is the exact input set."

Checkpoint

A durable record that a work unit ran with a specific input, config hash, output path, and checksum. It makes retries safe and explainable.

Staging

Temporary files produced while processing. Argus staging may be deleted only after durable commit, validation, reconciliation, and cleanup audit.

Durable Corpus

The long-lived local research database, currently data/argus.duckdb. It stores retained evidence and operational metadata.

Lineage

The ability to trace a row back to its origin: archive repo, revision, source file, manifest, batch, and source URL.

Reconciliation

Row-count accounting that proves inputs, rejected rows, retained rows, and quarantined rows add up as expected.

Mart

A curated analytical table or view shaped for research questions, such as pain points by subreddit or signal summaries.

Relevance Tier

A scored bucket for whether a candidate is retained, reviewed, evaluated, or discarded. Argus uses A/B/C/D-style thresholds.

Quality Gate

A measurable condition that must pass before widening scope, such as retained precision above the configured threshold.
