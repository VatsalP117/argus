# Mission: Onboard Into Argus Data Engineering

## Why
Learn the data engineering concepts needed to become productive in Argus as a fullstack developer. The practical goal is to understand the project well enough to debug pipeline runs, read schema/config changes, reason about data quality, and contribute safely to ingestion, scoring, querying, and evidence workflows.

## Success looks like
- Explain the Argus pipeline from remote Reddit Parquet archive to durable DuckDB research corpus.
- Read and modify a config, SQL check, migration, or Go command without breaking reproducibility contracts.
- Debug a failed scan, score, commit, validation, or query run using manifests, checkpoints, checksums, and row counts.
- Understand relevance precision/recall reports well enough to know when wider ingestion is blocked.
- Use the local query and ask layers while preserving evidence-backed output guarantees.

## Constraints
- Start from fullstack engineering knowledge, not prior data engineering experience.
- Teach from this repo first, with external resources used to clarify concepts.
- Favor short lessons with immediate checks over long theory dumps.
- Keep lessons local, printable, and easy to open in a browser.

## Out of scope
- Cloud warehouse administration.
- Real-time streaming architectures.
- Full ML model training.
- Building a production multi-user analytics product.
